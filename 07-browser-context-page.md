# 07 — Browser, Context, Page, Tabs, Frames, Dialogs, Shadow DOM

## 1. Browser vs BrowserContext vs Page

| Browser | BrowserContext | Page |
| ------- | -------------- | ---- |
| A browser instance (Chromium/Firefox/WebKit) | An **isolated incognito-like session** inside a browser | A single **tab** inside a context |
| Expensive to launch | Cheap & fast to create | Cheapest |
| Shared by tests in a worker | New one **per test** (isolation) | New one per test |
| `chromium.launch()` | `browser.newContext()` | `context.newPage()` |
| – | Owns cookies, localStorage, cache, permissions, geolocation | Owns DOM, frames, navigation |

```text
Browser
 ├── Context A (User: admin)   ── Page 1, Page 2
 └── Context B (User: customer) ── Page 1
```

```typescript
import { chromium } from '@playwright/test';

const browser = await chromium.launch({ headless: false, slowMo: 100 });
const context = await browser.newContext({ viewport: { width: 1440, height: 900 } });
const page = await context.newPage();
await page.goto('https://example.com');
await context.close();
await browser.close();
```

> A BrowserContext is like a fresh incognito profile. Playwright creates a new context for every test, giving full isolation — no shared cookies or storage — without the cost of launching a new browser.

### Built-in fixtures related to these

| Fixture | Scope | What |
| ------- | ----- | ---- |
| `browser` | worker | Shared browser instance |
| `context` | test | New context per test |
| `page` | test | New page in that context |
| `browserName` | worker | `'chromium' \| 'firefox' \| 'webkit'` |
| `request` | test | API request context |

## 2. Multiple Users in One Test (Multi-Context)

```typescript
test('admin and user chat', async ({ browser }) => {
  const adminCtx = await browser.newContext({ storageState: 'playwright/.auth/admin.json' });
  const userCtx  = await browser.newContext({ storageState: 'playwright/.auth/user.json' });

  const adminPage = await adminCtx.newPage();
  const userPage  = await userCtx.newPage();

  await adminPage.goto('/chat');
  await userPage.goto('/chat');

  await adminPage.getByRole('textbox').fill('Hello user');
  await adminPage.keyboard.press('Enter');
  await expect(userPage.getByText('Hello user')).toBeVisible();

  await adminCtx.close();
  await userCtx.close();
});
```

## 3. Multiple Tabs / New Windows / Popups

### New tab opened by a link (`target="_blank"`)

```typescript
const pagePromise = context.waitForEvent('page');
await page.getByRole('link', { name: 'Open in new tab' }).click();
const newPage = await pagePromise;

await newPage.waitForLoadState();
await expect(newPage).toHaveTitle(/Docs/);
await newPage.close();
await page.bringToFront();
```

### Popup (`window.open`)

```typescript
const popupPromise = page.waitForEvent('popup');
await page.getByRole('button', { name: 'Open popup' }).click();
const popup = await popupPromise;
await popup.getByRole('button', { name: 'Allow' }).click();
```

| `context.waitForEvent('page')` | `page.waitForEvent('popup')` |
| ------------------------------ | ---------------------------- |
| Any new page in the context | Only pages opened **by this page** |
| Good for tabs opened in any way | Good for `window.open` / target=_blank from a page |

### Switching between tabs

```typescript
const pages = context.pages();        // all open tabs
const second = pages[1];
await second.bringToFront();
```

### Open a new tab manually

```typescript
const tab2 = await context.newPage();
await tab2.goto('/settings');
```

## 4. iFrames

An **iframe** embeds another HTML document inside the page. Elements inside it aren't reachable from the main page locator.

```typescript
// Recommended: frameLocator
const frame = page.frameLocator('#payment-frame');
await frame.getByLabel('Card number').fill('4111111111111111');
await frame.getByRole('button', { name: 'Pay' }).click();

// Nested iframes
await page.frameLocator('#outer').frameLocator('#inner').getByText('Hi').click();

// From a locator
await page.locator('iframe[title="Payment"]').contentFrame().getByRole('button').click();

// Frame object (by name or URL)
const f = page.frame({ name: 'editor' }) ?? page.frame({ url: /editor/ });
await f?.fill('body', 'Hello');

// All frames
console.log(page.frames().length);
```

| `frameLocator()` ✅ | `page.frame()` |
| ------------------- | -------------- |
| Lazy, auto-waits for the iframe | Returns `Frame \| null` immediately |
| Works with locators & assertions | Older API |

> In Selenium you `switchTo().frame()` and must switch back. In Playwright you just scope locators with `frameLocator` — no switching.

## 5. JavaScript Dialogs (Alert / Confirm / Prompt)

A JavaScript browser dialog is a browser-level dialog generated by `alert()`, `confirm()`, `prompt()` or `beforeunload`.

### Types
1. **Alert** — Displays a message and requires acknowledgment.
2. **Confirm** — Provides OK / Cancel options.
3. **Prompt** — Accepts user input.
4. **beforeunload** — Appears when a page is about to be unloaded.

⚠️ **Default behaviour:** If there's **no** dialog listener, Playwright **auto-dismisses** dialogs. If you **add** a listener, you **must** call `accept()` or `dismiss()` — otherwise the page freezes and the action times out.

### Three Ways to Handle Dialogs

| `page.on('dialog')` | `page.once('dialog')` | `page.waitForEvent('dialog')` |
| ------------------- | --------------------- | ----------------------------- |
| Registers a **persistent** event listener | Registers a **one-time** event listener | Explicitly **waits for** a dialog event |
| Remains active for future dialogs | Removed automatically after first dialog | Returns a Promise for the dialog |
| Multiple dialogs throughout the test | Only one dialog expected | Synchronize dialog with the triggering action |
| Doesn't wait | Doesn't wait | Waits (fails on timeout) |
| Global / repeated handling | One-time handling | Action + dialog synchronization |

#### 1. `page.on('dialog')`

```typescript
page.on('dialog', async dialog => {
  console.log(dialog.type(), dialog.message());
  await dialog.accept();
});

await page.getByRole('button', { name: 'Delete' }).click();
await page.getByRole('button', { name: 'Delete Again' }).click();
```

```text
Dialog 1 → Handler
Dialog 2 → Handler
Dialog 3 → Handler
```

Remove it: `page.off('dialog', handler)` / `page.removeAllListeners('dialog')`.

> `page.on('dialog')` is used when I want a persistent dialog listener that handles every dialog during the test.

#### 2. `page.once('dialog')`

```typescript
page.once('dialog', async dialog => {
  expect(dialog.message()).toBe('Login successful');
  await dialog.accept();
});

await page.getByRole('button', { name: 'Login' }).click();
```

```text
First Dialog  → Handler → Listener removed
Second Dialog → No handler (auto-dismissed)
```

> `page.once('dialog')` registers a one-time listener — useful when only one dialog is expected.

#### 3. `page.waitForEvent('dialog')`

```typescript
const dialogPromise = page.waitForEvent('dialog');                   // 1. start waiting
const clickPromise = page.getByRole('button', { name: 'Delete' }).click(); // 2. trigger (don't await yet)
const dialog = await dialogPromise;                                  // 3. get dialog
expect(dialog.message()).toBe('Are you sure?');
await dialog.accept();                                               // 4. handle it
await clickPromise;                                                  // 5. click can now finish
```

⚠️ **Why not `await click()` first?** Browser dialogs are **modal** — the click that opens one does not complete until the dialog is accepted/dismissed. Because `waitForEvent` counts as a listener, Playwright won't auto-dismiss, so `await click()` → `await dialogPromise` → `accept()` can **hang**. Either keep the click promise un-awaited (above) or use a listener:

```typescript
page.once('dialog', d => d.accept());   // simplest & safest for blocking dialogs
await page.getByRole('button', { name: 'Delete' }).click();
```

### Examples per type

```typescript
// Alert
page.once('dialog', async d => { expect(d.type()).toBe('alert'); await d.accept(); });

// Confirm → Cancel
page.once('dialog', async d => { expect(d.type()).toBe('confirm'); await d.dismiss(); });
await page.getByRole('button', { name: 'Confirm' }).click();
await expect(page.locator('#result')).toHaveText('You clicked: Cancel');

// Prompt → type text
page.once('dialog', async d => {
  expect(d.type()).toBe('prompt');
  expect(d.defaultValue()).toBe('');
  await d.accept('Playwright');
});
await page.getByRole('button', { name: 'Prompt' }).click();
await expect(page.locator('#result')).toHaveText('You entered: Playwright');

// beforeunload
page.on('dialog', d => d.accept());
await page.close({ runBeforeUnload: true });
```

### Dialog methods

| Method | Purpose |
| ------ | ------- |
| `dialog.accept(text?)` | Click OK (optionally type text for prompt) |
| `dialog.dismiss()` | Click Cancel / close |
| `dialog.message()` | Text shown in dialog |
| `dialog.defaultValue()` | Default input value of a prompt |
| `dialog.type()` | `'alert' \| 'confirm' \| 'prompt' \| 'beforeunload'` |
| `dialog.page()` | Page that opened the dialog |

### HTML modals (not browser dialogs)

A custom modal (`<div role="dialog">`) is just DOM — handle with locators:

```typescript
const modal = page.getByRole('dialog', { name: 'Delete item' });
await expect(modal).toBeVisible();
await modal.getByRole('button', { name: 'Confirm' }).click();
```

### Random overlays (cookie banners, newsletter popups)

```typescript
await page.addLocatorHandler(page.getByRole('button', { name: 'Accept cookies' }), async btn => {
  await btn.click();
});
```

> `addLocatorHandler` automatically dismisses an overlay whenever it appears before an action.

## 6. Shadow DOM

- Playwright CSS and `getBy*` locators **pierce open shadow roots automatically**.
- **XPath does not** pierce shadow DOM.
- **Closed** shadow roots are not accessible.

```typescript
await page.locator('user-card').getByRole('button', { name: 'Follow' }).click();
```

## 7. Page Events

```typescript
page.on('console', msg => console.log(`[${msg.type()}] ${msg.text()}`));
page.on('pageerror', err => console.log('JS error:', err.message));
page.on('request', req => console.log('>>', req.method(), req.url()));
page.on('response', res => console.log('<<', res.status(), res.url()));
page.on('requestfailed', req => console.log('FAILED', req.url()));
page.on('load', () => console.log('loaded'));
page.on('close', () => console.log('closed'));
```

Fail the test on any console error:

```typescript
const errors: string[] = [];
page.on('console', m => { if (m.type() === 'error') errors.push(m.text()); });
// ... test ...
expect(errors).toEqual([]);
```

## 8. Cookies, Local Storage, Permissions

```typescript
await context.addCookies([{ name: 'token', value: 'abc', url: 'https://app.com' }]);
const cookies = await context.cookies();
await context.clearCookies();

await page.evaluate(() => localStorage.setItem('theme', 'dark'));
const theme = await page.evaluate(() => localStorage.getItem('theme'));

await context.grantPermissions(['geolocation', 'notifications', 'clipboard-read'], { origin: 'https://app.com' });
await context.clearPermissions();
```

## 9. Screenshots & PDF from a Page

```typescript
await page.screenshot({ path: 'page.png', fullPage: true });
await page.getByTestId('chart').screenshot({ path: 'chart.png' });
await page.pdf({ path: 'page.pdf', format: 'A4' });  // Chromium only
```

> **Interview one-liner:** Browser is the process, BrowserContext is an isolated incognito session, and Page is a tab. Each test gets its own context for isolation. I handle new tabs with `context.waitForEvent('page')`, popups with `page.waitForEvent('popup')`, iframes with `frameLocator`, and JS dialogs with `page.on/once('dialog')` — remembering that once a listener exists I must accept or dismiss.
